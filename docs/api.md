# API Documentation

Base URL (development): `http://127.0.0.1:8000`
All request/response bodies are JSON. Interactive Swagger docs are also
auto-generated by FastAPI at `GET /docs`.

---

## GET /api/health

Purpose: report backend readiness — whether the configured compiler is on
PATH and whether an LLM API key is configured. Used by the frontend sidebar
on load.

**Request body:** none

**Response body:**
```json
{
  "status": "ok",
  "compiler": "g++",
  "compiler_available": true,
  "llm_configured": true,
  "llm_model": "openai/gpt-oss-20b"
}
```

**Errors:** none expected (this endpoint does not touch the compiler or LLM,
only checks their availability).

## POST /api/analyze

Purpose: run the **complete pipeline** — preprocessing, static analysis, AI
optimization, compilation, correctness testing, benchmarking, and the
accept/reject decision — in a single call. This is the endpoint the frontend
uses to drive the whole console.

**Request body** (`AnalyzeRequest`):
```json
{
  "source_code": "#include <iostream>\nint main(){ std::cout << 1; return 0; }",
  "test_cases": [
    { "name": "basic", "stdin": "", "expected_stdout": null, "timeout_seconds": null }
  ]
}
```
`test_cases` may be an empty array; the pipeline then runs with a single
default case using empty stdin.

**Response body** (`AnalysisReport`, abbreviated):
```json
{
  "id": "a1b2c3d4e5f6",
  "original_code": "...",
  "preprocess": { "ok": true, "errors": [], "warnings": [], "line_count": 8, "looks_like_cpp": true },
  "static_analysis": { "findings": [ { "type": "nested_loop", "severity": "medium", "line": 4, "message": "...", "recommendation": "...", "confidence": 0.8 } ], "summary": "...", "estimated_complexity": "O(n^2)" },
  "ai_result": { "analysis": "...", "optimizations": [...], "optimized_code": "...", "explanation": "...", "complexity_before": "O(n^2)", "complexity_after": "O(n)", "no_safe_optimization": false, "raw_error": null },
  "original_compilation": { "success": true, "stdout": "", "stderr": "", "command": "g++ ...", "binary_path": "/tmp/.../program.out", "timed_out": false },
  "optimized_compilation": { "success": true, "...": "..." },
  "correctness": { "all_passed": true, "total": 1, "passed_count": 1, "results": [ { "name": "basic", "passed": true, "...": "..." } ] },
  "benchmark": { "original": { "mean_time_seconds": 0.041, "...": "..." }, "optimized": { "mean_time_seconds": 0.019, "...": "..." }, "time_improvement_percent": 53.7, "verdict": "faster", "memory_improvement_percent": null },
  "decision": { "status": "ACCEPTED", "reasons": ["Compilation successful for both versions.", "..."], "checklist": { "original_compiled": true, "optimized_compiled": true, "correctness_passed": true, "performance_improved": true } },
  "stages": [ { "stage": "preprocessing", "status": "completed" }, "..." ],
  "error": null
}
```

**Errors:**
- `400`/`422` — `source_code` empty or request body malformed (FastAPI/Pydantic validation error).
- `500` — unexpected internal error; the global exception handler in `main.py` guarantees a JSON `{"detail": "..."}` body rather than a blank page.
- A **non-fatal** pipeline error (empty source, unbalanced braces, missing `LLM_API_KEY`, LLM/network failure, malformed AI JSON) is returned as `200 OK` with `error` populated and `stages` showing exactly which stage failed/was skipped — this lets the frontend render *why* the pipeline stopped instead of just a generic failure.

## POST /api/compile

Purpose: standalone compilation check (used internally by the pipeline; also
useful for debugging without running the whole flow).

**Request body:**
```json
{ "source_code": "int main(){ return 0; }" }
```

**Response body** (`CompilationResult`):
```json
{ "success": true, "stdout": "", "stderr": "", "command": "g++ -std=c++17 -O2 -Wall /tmp/.../program.cpp -o /tmp/.../program.out", "binary_path": "/tmp/.../program.out", "timed_out": false }
```

**Errors:** none raised; failures are reported via `success: false` and a
populated `stderr`/`timed_out` field rather than an HTTP error, since a
compile failure is an expected, meaningful outcome.

## POST /api/test

Purpose: standalone correctness comparison — compiles both an original and
an optimized candidate, then runs the supplied test cases against both.

**Request body:**
```json
{
  "original_code": "...",
  "optimized_code": "...",
  "test_cases": [ { "name": "t1", "stdin": "5\n" } ]
}
```

**Response body** (`CorrectnessResult`):
```json
{ "all_passed": true, "total": 1, "passed_count": 1, "results": [ { "name": "t1", "passed": true, "stdin": "5\n", "original_stdout": "25\n", "optimized_stdout": "25\n", "...": "..." } ] }
```

**Errors:**
- `400` — either program failed to compile (detail includes the compiler stderr).

---

## POST /api/benchmark

Purpose: standalone benchmarking — compiles both versions and benchmarks
them under identical conditions with a single supplied stdin.

**Request body:**
```json
{ "original_code": "...", "optimized_code": "...", "stdin_data": "" }
```

**Response body** (`BenchmarkResult`):
```json
{
  "original": { "mean_time_seconds": 0.04, "min_time_seconds": 0.038, "max_time_seconds": 0.043, "peak_memory_kb": 1820.0, "memory_available": true, "runs": 5, "failed": false, "failure_reason": null },
  "optimized": { "mean_time_seconds": 0.02, "...": "..." },
  "time_improvement_percent": 50.0,
  "verdict": "faster",
  "memory_improvement_percent": 3.1
}
```

**Errors:**
- `400` — either program failed to compile.

## GET /api/report/{report_id}

Purpose: retrieve a previously computed `AnalysisReport` by its id (every
successful `/api/analyze` call persists its report to
`REPORT_STORE_DIR/{id}.json`).

**Response body:** same shape as the `/api/analyze` response.

**Errors:**
- `404` — no report exists with that id.
